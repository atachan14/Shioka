# コンセプトと設計意図

## 初期資料に残る中心

Shioka は「真にオモロイ格ゲー」の略。初期資料は格闘ゲームの魅力を **駆け引き・アクション・キャラ表現** と整理し、固定されたコンボやフレームの暗記だけでなく、状況に応じた即興的なアクションを増やすことを目指していました。

そのための特徴は、HitBox の攻撃強度 A と HurtBox の防御 D、TG によって、接触結果・硬直・ダメージ・その後の展開が変わることです。部位や技の時間による変化をデータとして調整できる方向です。TRC は残り硬直に応じて TG を支払い、被弾硬直を含む状態からの行動選択を増やす構想です。

出典は旧アーカイブの `docs/concept.md` と `docs/imported/shioka2/{concept,combat_model,v0.1}.md`。保管・取得方法は [移行記録](DOCS_HISTORY.md)。これは初期意図の要約で、旧数式を現行に採用し直す指示ではありません。

## 維持する実装上の要件

- 60Hz の戦闘フレームを基準にし、入力、行動、描画の時計と停止条件を区別する。
- キーバインドの違いで同じキャラのコマンド成立条件が変わらないこと。同時押し確定待ちは撤廃した。
- 同じキャラは同じ調整データを参照。入力主体・左右の違いと性能差を混同しない。
- 移動性能、技性能、画像表示時間、画像位置、本体移動、Hit/HurtBox を分け、画像枚数変更で技性能を変えない。
- 個別 asset から編集し、明示保存する。プレビュー・個人設定・正式調整値に複数の正本を作らない。
- Unity の 2D 表示・Physics2D を使う。将来のネット対戦を理由に、未実装の rollback や跨環境決定性を保証しない。

## 初期案からそのまま持ち込まないもの

初期の TG 加算式、差分レベル式、ガードブレイク案、直ガの防御加算案、SDC の旧名称・例示コストは後続仕様と異なります。現在の式は [CURRENT_SPEC](CURRENT_SPEC.md)。初期資料の「コマンド無し」「3対3」等は将来案・再確認対象で、現在の確定機能として実装しません。初期 v0.1 の「キャラ選択は対象外」も当時の範囲であり、後の Title / Player・CPU 選択実装を否定しません。
