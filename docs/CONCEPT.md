# コンセプト

Shioka は「真にオモロイ格ゲー」の略。

## 目指すもの

格闘ゲームがほかのジャンルより優れている点は、**駆け引き・アクション・キャラ表現**の3つ。今の格闘ゲームは、固定フレームを使ったコンボやセットプレイのパズル的な面が強調され、アクションゲームとしての可能性を活かしきれていない。パズル的な面も格ゲーの面白さだが、ほかのジャンルでも代わりがきく。

Shioka は、その場の状況に応じた**即興的なアクション**が成り立つ格闘ゲームを目指す。

## 中心になる考え方

- **ヒットとガードの間をグラデーションにする。** 攻撃判定には攻撃の強さ、食らい判定には防御の強さを持たせ、その差で、ヒットか、ガードに近い当たり方か、どれだけ硬直するかが決まる。同じ技を同じように当てても、当てたフレームやゲージの状況で、その後の展開が変わる。
- **テンションゲージ(TG)が攻防の強さに効く。** ゲージは100%を超えることも、マイナスになることもある。使い続けることはできるが、マイナスになると攻撃も防御も弱くなる。
- **硬直をキャンセルできる。** 食らい硬直を含め、残りの硬直に応じたゲージを払って行動をやり直せる(TRC)。
- **タイミングの良さを段階的に評価する。** 直前ガードなどを「成立/不成立」ではなく、タイミングに応じた強さで扱う。
- 攻撃中の防御の強さも技ごとに決められるので、強いアーマー・弱いアーマーを持つ技を作りやすい。差し合いは、発生の速さだけでなく、アーマー前提の読み合いになる。
- **コマンド入力(236P のような入力)はなし。** 技は、ボタン単独か、レバー入れ攻撃(6P、3P など)だけで出す。これは今も重要な前提。会話や資料では、レバー入れ攻撃のことを「コマンド技」と呼んでいる場合がある。(2026-10-29 ユーザー確認)
- **当面は1対1に集中する。** 3対3とアシストは、ずっと先の将来の要件として目指す。(2026-10-29 ユーザー確認)

具体的な式と現在の扱いは [spec/combat.md](spec/combat.md)。

## Mania と Delirium(構想)

- **Mania**: 旧称 Force の後継。TG を使って各行動を強化する修飾。Boost などより世界観の出る名前を探して、「躁」の語感から選んだ。当時の構想は次のとおり。
  - 後ろ + Mania で FD(これは実装済み)
  - 技と組み合わせて攻撃の強さを上げる(通常技も超必殺も対象)
  - ダッシュ・空中ダッシュの速度と防御の強さを上げる
  - バックステップの強化(無敵の延長か距離の延長かは未決)
  - ジャンプを高くする
  - 投げを、通常の投げ抜けでは抜けられず、Mania 投げ抜けでなら抜けられるようにする
  - TG が0以下では使えない
- **Delirium**: Mania と対になる、さらに歪んだ雰囲気の超必殺側の名前。暗転を含む TG 消費技のカテゴリーで、専用のボタンは設けない。
- どちらも構想で、効果・消費量・適用条件・暗転の時間・D1〜D3 への割り当ては未確定。今の FD の入力と、今後の強化機能は分けて扱う。Mania の構想は上のとおりで、それ以上の詳細はまだ未定(2026-10-29 ユーザー確認)。
- **Hold**: 投げの改名(ユーザー確認済み)。命名の理由は確定していない。

## 初期案から変えたこと

初期資料にはあるが、今の仕様とは違うもの。変えた理由が分かっているものは書いておく。

- **TG の効き方を「加算」から「倍率」にした。** TG が A・D にもパンチの強さにも加算で関わり、効果が重なっていたのを見直した。2026-10-24 にユーザー自身が「A や D への TG の加算をやめ、強さとの関係も乗算にする」と提案した。TG100 で1.5倍、200で2倍、300で2.5倍。同じ TG 差100でも、高い TG どうしほど相対的な差が小さくなることも、明示的に了承している。実装の都合で変えたものではない。
- **ガードブレイクをなくした。** 「閾値を境に挙動が急変するのが気持ち悪い」「なるべく状態や挙動をグラデーションにしたい」というコンセプトから。2026-10-24 に、対応するガードを入力していれば H が高くてもガードになり、強さは大きなヒットバックや壁際でのダウンで表す方向に変えた。
- **キャンセルの名前**: 真どこでもキャンセル(SDC)→ 2026-10-11 に TrueDokodemoCancel(TDC)→ 2026-10-12 に「GG(ギルティギア)に敬意を表して」TRC。SDC から TDC への変更理由は確認できていない。初期の例示のコスト(1Fにつき5%など)も今の仕様ではない。
- 初期のゲージ補正(ゲージ1%につき強さ+1)、ガードクラッシュ、直前ガードの初期の数値は、今の式とは別([spec/combat.md](spec/combat.md))。
- 「テンションレベルによるゲージ増加量の補正」は、将来案として残っているだけで、確定した仕様ではない。

これらの経緯は、Dot が当時の会話と旧資料・今のコードを照らし合わせて確認したもの(2026-10-29)。
